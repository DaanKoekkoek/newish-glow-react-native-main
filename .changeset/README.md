# Changesets

Hello and welcome! This folder has been automatically generated by `@changesets/cli`, a build tool that works with multi-package repos or single-package repos to help you version and publish your code. You can find the full documentation for it [in our repository](https://github.com/changesets/changesets).

## Versioning Strategy

In our project, we adhere to the following versioning conventions:

- **Patch (`0.0.x`)**: Reserved for small bug fixes or minor changes to existing components that do not introduce new features or breaking changes.

- **Minor (`0.x.0`)**: Used when introducing new components or adding new functionality in a backward-compatible manner.

- **Major (`x.0.0`)**: Applied for significant overhauls or changes that include breaking changes, requiring consumers to modify their usage accordingly.

This approach aligns with semantic versioning principles, ensuring that version numbers convey meaningful information about the nature of changes in each release.

## Using Changesets

To implement this versioning strategy with Changesets, follow these steps:

1. **Creating a Changeset**: When you make changes that need to be released, create a changeset by running:

```bash
pnpm changeset
```

A markdown file will be generated, giving you the option to update the changeset.

2. **Version bump**: Before merging your PR, squash your created changeset by running:

```bash
pnpm changeset:version
```
