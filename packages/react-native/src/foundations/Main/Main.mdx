# Main

The `<Main>` component serves as a top-level container for rendering a virtualized list of sections, headers, and footers. It provides a structured layout, ensuring that content is organized into distinct sections and can be efficiently rendered and managed.

## Key features

1. **Only Accepts [`Section`](?path=/docs/designsystem-layout-section--docs)**: The `<Main>` component only accepts `<Section>` components as children, which are used to organize the content into distinct sections.
2. **Header and Footer Support**: Includes support for `Header` and `Footer` components to display content at the top and bottom of the list.
3. **Sticky Header**: The `hasStickyHeader` property keeps the header visible at the top of the screen while scrolling.
4. **Virtualized List with `SectionList`**: Uses React Native's `SectionList` to efficiently render large lists by only rendering items currently visible on the screen.
5. **Web Compatibility**: Wraps content in a `<main>` tag for web applications, enhancing accessibility and semantics.

**Note: Since there is a `min-width` applied on the `<Grid>`, it is recommended to preview the grid on their respective pages instead of the Docs.**

### Pre requirements

To be sure that the `<Main />` works as expected you need to wrap your `<App />` with the `<SafeAreaProvider />` at root level.
Because the main contains features that do need the the `<SafeAreaProvider />`.
The SafeAreaProvider takes into account system elements (status bar, notches, etc.), these values will be provided to descendent consumers.
This is to make sure there is not content overlapping with the system elements.

**Example:**

```jsx
import { SafeAreaProvider } from "react-native-safe-area-context";

export default function App() {
  return (
    <SafeAreaProvider>
      <View>{/*The rest of your app*/}</View>
    </SafeAreaProvider>
  );
}
```
